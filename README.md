# Jev-Guided Go Program Synthesis

**자연어 설명과 입출력 예제로 Go 함수를 만들고, 코드가 만들어지는 과정을 살펴보는 실험 도구입니다.** 로컬 웹 화면과 CLI를 제공합니다.

예를 들어 “정수 a에서 b를 뺀 값을 반환한다”는 설명과 `a=7, b=2 → 5` 같은 사례를 입력합니다. 도구는 가능한 Go 토큰을 제시하고, 모델이 고른 토큰을 하나씩 이어 붙여 함수를 탐색합니다. 완성된 코드는 컴파일하고 주어진 사례로 실행해 확인합니다.

완성 코드를 한 번에 생성하는 대신, **모델의 선택이 어떤 코드로 이어지는지 관찰하고 비교**할 수 있습니다. 작은 함수의 합성 과정이나 모델별 후보 선택을 살펴보려는 사용자에게 적합합니다.

## 할 수 있는 일

- **생성 과정 보기:** 웹 화면에서 Beam-3 탐색이 유지하는 최대 세 코드 경로와 다음 토큰 후보를 확인합니다.
- **작은 Go 함수 만들기:** 설명, 입력 이름, 허용 타입과 입출력 사례를 JSON으로 지정해 합성합니다. 함수 이름과 서명도 생성 과정에 포함됩니다.
- **모델과 탐색 전략 비교:** Jev, 로컬 Decider 또는 테스트용 fake 순위기로 예제 문제를 실행합니다. CLI에서는 greedy, strict-greedy, beam 전략을 비교할 수 있습니다.
- **기록 다시 보기:** 웹의 저장 기록과 단계 재생으로 이전 탐색을 살펴보고, 최종 코드·결과 JSON·trace를 내려받습니다. 기록 재생은 모델을 호출하지 않습니다.

## 빠르게 체험하기

[Go](https://go.dev/) 1.24 이상을 설치하고 저장소 루트에서 실행합니다. 웹 화면은 Go 서버에 포함되어 별도 Node.js 설치나 프론트엔드 빌드가 필요하지 않습니다.

```powershell
go run ./cmd/web
```

브라우저에서 [http://127.0.0.1:8080/](http://127.0.0.1:8080/)을 열고, 문제와 모델을 선택한 뒤 **탐색 시작**을 누르세요.

처음에는 기본값인 **fake**로 화면과 실행 흐름을 확인할 수 있습니다. fake는 API 키나 모델 서버가 필요 없는 고정 순위기입니다. 요구사항의 의미를 이해하지 않으므로 문제를 풀지 못할 수 있으며, 결과는 AI 성능을 나타내지 않습니다.

웹 화면에서는 다음 기능을 제공합니다.

| 기능 | 동작 |
|---|---|
| 코드창 선택 | 해당 경로의 다음 토큰 후보를 표시합니다. **전체**를 선택하면 모든 후보를 봅니다. |
| 화면 일시정지 | 화면 갱신만 멈춥니다. 합성과 모델 호출은 계속됩니다. |
| 실시간 복귀 | 현재 진행 상태로 돌아갑니다. |
| 중지 | 실제 실행을 취소하고 부분 결과와 미실행 문제를 저장합니다. |
| 전체 40문제 | 선택한 모델로 Beam-3 합성을 40회 순차 실행합니다. |
| 저장 기록·단계 재생 | 이전 실행의 문제별 기록과 생성 과정을 확인합니다. |

브라우저를 닫아도 실행은 취소되지 않습니다. 다시 접속하면 최신 상태를 확인할 수 있습니다. 서버는 로컬 접속만 허용하며, 한 번에 하나의 실행 묶음을 진행합니다.

## 실제 모델 사용하기

| 선택지 | 준비할 것 |
|---|---|
| Jev | API 인증 환경. 사용량에 따른 호출 비용이 발생할 수 있습니다. |
| 로컬 Decider | `Mapika/decider-4b` 추론 서버. [로컬 모델 실행 안내](runtime/README.md)를 참고하세요. |
| fake | 추가 준비 없이 실행 가능. 화면과 실행 흐름 확인용입니다. |

기본 웹 설정은 `examples/token/compare-live.json`의 Jev·Decider와 fake를 제공합니다. Jev 인증은 서버를 시작하는 환경에서 설정하며, 브라우저에 API 키를 입력하지 않습니다. 실제 모델은 선택한 뒤 실행을 시작할 때 사용합니다.

주소, 모델·문제 설정, 결과 저장 위치를 바꾸려면 다음처럼 실행합니다.

```powershell
go run ./cmd/web -listen 127.0.0.1:8081 -manifest examples/token/compare-jev.json -output output
```

## CLI로 함수 만들기

다음은 포함된 뺄셈 문제를 fake로 실행하고 탐색 기록을 저장하는 예입니다.

```powershell
go run ./cmd/synth -spec examples/token/specs/arithmetic-subtract.json -heldout examples/token/heldout/arithmetic-subtract.json -ranker fake -trace
```

Jev를 사용하려면 인증 환경을 준비한 뒤 실행합니다. `-key-env`에는 키 값이 아닌 환경변수 이름을 지정합니다.

```powershell
go run ./cmd/synth -spec examples/token/specs/arithmetic-subtract.json -heldout examples/token/heldout/arithmetic-subtract.json -ranker jev -model jev-latest -key-env TYPESAFE_API_KEY -trace
```

직접 문제를 만들 때는 다음 형태의 JSON을 사용합니다. 정답 코드나 함수 서명을 제공할 필요는 없습니다.

```json
{
  "intent": "정수 a에서 b를 뺀 값을 반환한다.",
  "inputs": ["a", "b"],
  "allowed_types": ["int"],
  "literals": {"integers": [0, 1], "strings": []},
  "public_tests": [{"inputs": {"a": 7, "b": 2}, "want": 5}]
}
```

`public_tests`는 생성 중 검증에 쓰는 사례입니다. `-heldout`은 완성 후보를 고정한 뒤 별도로 평가할 사례 파일이며, 그 결과로 다시 탐색하지 않습니다. 빈 컬렉션처럼 사례만으로 타입을 정할 수 없다면 `type_hints`와 `output_type_hint`를 지정합니다. 자세한 사례와 비교 설정은 [40문제 안내](examples/token/README.md)를 참고하세요.

## 결과 확인하기

CLI의 최종 결과는 화면에 출력되고 현재 작업 디렉터리의 `output/`에도 JSON으로 저장됩니다. 파일명은 한국 시간 기준 `yyyy-dd-mm.nnn` 형식입니다. 예를 들어 2026년 11월 5일의 첫 결과는 `2026-05-11.001`이며, 별도 `.json` 확장자는 붙지 않습니다.

결과에는 성공 여부뿐 아니라 예산 소진·후보 소진·모델 오류 등 종료 상태, 호출 수와 실행 시간이 담깁니다. `-trace`를 사용하면 같은 이름의 `.trace.jsonl` 파일에 토큰 선택 과정을 기록합니다. 웹에서 실행한 기록은 웹 화면에서 다시 열 수 있습니다.

문제 세트와 전략을 함께 비교하려면 다음 명령을 사용합니다.

```powershell
go run ./cmd/compare -manifest examples/token/compare-smoke.json -trace
```

이 설정은 fake로 두 문제와 세 전략을 실행합니다. 실제 모델 비교 설정은 [문제 세트 안내](examples/token/README.md)에 있습니다. 모델이 반환한 사용량과 사용자가 설정한 단가가 있을 때만 비용을 추정하며, 알 수 없는 비용은 0으로 처리하지 않습니다.

## 지원 범위와 한계

현재는 단일 Go 함수의 제한된 문법을 탐색합니다.

- **타입:** `int`, `bool`, `string`, `[]int`, `[]string`, `map[string]int`, `map[string]string`
- **구문:** 지역 변수, 대입, 조건문, `for`·`range`, 인덱싱과 컬렉션 조작
- **호출:** `len`, `cap`, `append`, `copy`, `delete`, `make`와 지원 타입 변환

보조 함수, 재귀, 외부 패키지, 구조체, 인터페이스, 제네릭, 동시성은 지원하지 않습니다. 탐색에는 토큰 수·호출 수·시간 등의 한도가 있어 해를 찾지 못하거나 예산이 소진될 수 있습니다. 옵션은 `go run ./cmd/synth -help`로 확인할 수 있습니다.

테스트 통과는 제공한 사례에서의 동작을 확인한 결과이며 모든 입력에 대한 정당성 증명은 아닙니다. 저장소의 최종 평가 사례도 공개되어 있으므로 미공개 평가를 대신하지 않습니다. fake 실행이나 참조 코드 검증으로 실제 모델의 문제 해결 성능을 판단할 수 없습니다.

생성 코드는 별도 프로세스에서 시간·출력 제한을 두고 실행하지만, 운영체제 sandbox나 메모리 격리를 제공하지 않습니다. 명세와 문자열 리터럴에는 비밀정보를 넣지 마세요. 토큰 trace에도 생성된 리터럴이 기록됩니다.

기존 AST 합성 엔진은 CLI의 `-engine ast`로 사용할 수 있습니다. [AST 문제 세트 안내](examples/suite/README.md)를 참고하세요. AST 결과와 완성 후보 선택 벤치마크는 기본 토큰 합성 결과와 구분해서 해석해야 합니다.
