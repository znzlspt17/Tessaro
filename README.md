# JevCanCode

자연어 설명과 입출력 사례를 바탕으로 Go 함수를 탐색하고, 코드가 만들어지는 과정을 관찰하는 Windows 11 네이티브 프로그램입니다.

`JevCanCode.exe`에서 실행·기록·모델 비교·후보 벤치마크를 다룹니다. GUI와 Go 탐색 엔진은 같은 프로세스에서 동작합니다. Decider는 프로그램이 관리하는 Python 추론 워커로 실행하며 로컬 서버나 브라우저를 사용하지 않습니다.

## 실행

개발 환경에서 실행 파일을 만듭니다. Go 1.24 이상과 PowerShell이 필요합니다.

```powershell
.\scripts\build-desktop.ps1
```

생성된 `dist/JevCanCode.exe`를 더블클릭하세요. 설정에서 프로젝트·출력·Python·모델 경로를 확인할 수 있습니다. 현재 PC의 `.venv-rocm72`와 `runtime/models/decider-4b`를 재사용합니다. 다른 PC용 설치 프로그램이나 모델은 포함하지 않습니다.

생성 코드의 컴파일·실행 검증에는 Go 도구가 필요합니다. 로컬 모델 환경 준비는 [런타임 안내](runtime/README.md)를 참고하세요. 이미 준비된 환경은 다시 설치하거나 다운로드할 필요가 없습니다.

## 사용하기

- **탐색:** 문제, 모델, token/AST 엔진, 전략과 예산을 선택해 실행합니다. 기본 모델은 Decider이며 한 번에 하나의 작업을 실행합니다. 유지된 코드 경로, 후보 점수, 판단 문맥과 차단 이유를 살펴볼 수 있습니다.
- **기록:** 실행과 문제를 선택해 저장 결과를 엽니다. trace가 있는 기록은 단계별로 재생하고 코드·결과·trace를 저장할 수 있습니다.
- **비교:** 기존 비교 manifest를 열어 모델·문제·전략·반복별 결과를 확인합니다.
- **후보 벤치마크:** 완성 후보 중 정답의 순위를 평가합니다. 함수 합성의 성공률과는 다른 평가입니다.
- **가설 검증:** 비교 / 벤치마크 화면에서 Jev의 토큰 선택 능력을 평가합니다. 참조 경로 도달성, 정상 코드 앞부분의 다음 토큰 판단, 빈 코드부터의 함수 생성을 구분합니다.
- **설정:** 프로젝트·결과·Python·모델 경로와 준비 상태를 확인합니다.

화면 일시정지는 화면 갱신만 멈춥니다. 실제 탐색은 계속되며 실시간 복귀 시 최신 상태를 봅니다. 중지는 실행을 취소하고 부분 결과를 보존합니다. 프로그램을 닫으면 실행을 취소하고 자신이 생성한 추론·검증 프로세스를 정리합니다.

### 판단 관찰 화면

탐색 화면은 넓은 모니터에 맞춰 판단 이력, 코드와 후보, 모델 판단의 세 영역으로 구성됩니다. 경계를 드래그해 너비를 조절할 수 있습니다. 후보 행을 선택하면 해당 부모 코드와 추가할 토큰의 미리보기를 함께 확인합니다. 검사에서 제외된 후보는 모델 요청 후보와 구분합니다.

코드는 기본 16pt로 크게 표시하며 A−/A+로 크기를 조절합니다. 실제 유지 코드와 후보 미리보기는 한 영역에서 탭으로 전환합니다. ‘코드 집중’은 주변 패널을 접고, ‘집중 종료’는 기본 화면으로 돌아갑니다. ‘자동 스크롤’을 끄면 갱신 중에도 읽던 위치를 유지할 수 있습니다.

모델이 직접 선택한 후보와 탐색기가 유지한 경로는 다른 정보입니다. 특히 beam 탐색은 여러 경로를 유지할 수 있고, 동점 점수의 정렬상 1위가 모델의 실제 선택과 다를 수 있습니다. 새 기록은 검증된 응답의 선택 ID를 보존합니다. 예전 기록에 선택 ID가 없으면 실제 선택을 추측하지 않고 점수상 1위와 구분해 표시합니다.

판단 문맥이 준비되었다고 전송 완료를 의미하지는 않습니다. 요청 준비, 호출 중, 응답 수신, 실패를 구분하며, 후보가 하나라 모델 호출 없이 진행한 경우는 자동 확정으로 표시합니다. 기본 재생은 판단 단위이며 개별 이벤트도 확인할 수 있습니다. 표시용 코드 정렬은 원본 토큰을 수정하지 않습니다.

모델 로딩 시간과 추론 요청 시간을 구분합니다. Decider 준비 제한시간은 기본 180초, 각 요청은 기본 60초입니다. 탐색 예산은 모델 준비 후 시작합니다. 준비 실패·취소·시간 초과 후에는 다음 실행에서 워커를 새로 만듭니다.

## 모델과 입력

Decider는 ROCm GPU 환경을 사용하며 CPU로 자동 대체하지 않습니다. Jev는 외부 API 모델로 기존 환경 기반 인증을 사용합니다. 프로그램에 인증값을 입력하거나 기록에 저장하지 않습니다. 실제 호출에는 비용이 발생할 수 있습니다.

일반 모델 목록에는 Fake가 없습니다. Fake는 자동 테스트용 고정 순위기이며, 구형 Fake 비교 설정은 실제 모델로 바꿔 실행해야 합니다. 기존 Decider 설정의 localhost URL은 관리형 워커로 연결하지만 다른 모델이나 사용자 지정 endpoint를 임의로 Decider로 바꾸지는 않습니다.

[기본 token 문제 40개](examples/token/README.md)와 [AST 문제 24개](examples/suite/README.md)를 제공합니다. JSON의 공개 사례는 탐색에 사용하고 별도 평가 사례는 제출 후보가 정해진 뒤 읽습니다. 참조 코드는 개발 테스트와 가설 검증의 평가 계층에서만 읽으며, 일반 생성의 모델 요청에는 전달하지 않습니다.

### Jev 가설 검증

전용 입력은 `examples/token/hypothesis.json`입니다. 일반 탐색에서 선택한 모델과 관계없이 `jev-1.14.0`을 사용하며 다른 버전으로 자동 대체하지 않습니다. 실제 실행은 사용자가 앱의 **가설 검증**에서 시작합니다. API 호출에는 요금이 발생하며, 최대 10,000회 요청 제한은 금액 제한이 아닙니다.

먼저 모델 호출 없이 실제 탐색기를 따라 참조 코드의 도달성을 검사합니다. 이어서 문제마다 최대 48개 판단 위치를 원래 후보 ID와 재배치한 ID로 평가하고, 40문제의 전체 생성을 `strict-greedy`와 `beam`으로 비교합니다. 무작위 기준선은 seed 42·43·44를 사용합니다. 강제 선택, 참조 경로 차단, 미확인 선택, 검증 실패와 예산 소진은 별도로 기록합니다.

참조 코드와 다른 토큰 선택을 곧바로 오답으로 세지 않습니다. 참조 경로 유지율과 전체 함수의 테스트 통과율은 다른 지표입니다. 중지한 실행도 부분 결과를 보존하며, 기록에는 구조화된 결과와 한국어 요약 보고서가 남습니다. 실제 Jev 결과가 없으면 가설의 지지 여부를 판단하지 않습니다.

## 저장 기록과 한계

기존 웹 실행·단일 합성·비교·후보 벤치마크 결과를 읽습니다. 원본 파일을 변환하거나 이름을 바꾸지 않습니다. 새 기록은 `desktop_run` 형식 버전 1을 사용합니다. 미완료 실행은 중단된 기록으로 표시하며 프로그램을 다시 열어도 자동 재실행하지 않습니다.

실제 trace가 없는 결과에서 단계를 만들어 내지 않습니다. 오래된 기록에 후보 코드나 판단 문맥이 없으면 해당 정보가 없다고 표시합니다. 비교·벤치마크는 각 보고서의 실제 데이터만 보여줍니다.

이 도구는 제한된 Go 부분집합과 예산 안에서 탐색합니다. 정답을 찾지 못하거나 예산을 소진할 수 있습니다. 제공한 테스트의 통과는 모든 입력에 대한 정당성 증명이 아닙니다. 저장소의 별도 평가 사례도 공개되어 있으므로 비공개 일반화 평가를 대신하지 않습니다.

## 개발 검증

```powershell
.\scripts\test-headless.ps1 -PythonPath '.\.venv-rocm72\Scripts\python.exe'
```

Python 경로는 사용하는 환경에 맞게 지정합니다. Go 전체 테스트와 Python 워커의 fake 단위 테스트를 실행하고 각 단계의 상태, 소요 시간, 종료 코드를 JSON으로 출력합니다. GPU smoke는 명시적으로 비활성화하며 모델을 호출하지 않습니다. `-Race`는 CGO와 C 컴파일러가 준비된 경우 race 검사를 실행하고, 조건이 부족하면 그 이유와 함께 건너뜁니다. 도구를 설치하지 않습니다.

Windows 컨트롤을 수정했을 때는 `-Native`를 추가합니다. 이 검사는 제품 manifest를 포함해 실제 컨트롤을 생성합니다. 또는 다음 명령으로 따로 실행할 수 있습니다.

```powershell
.\scripts\test-desktop.ps1
```

### 창 없는 연구 실행

연구 입력은 기존 40개 개발 문제와 별도 20개 평가 문제를 사용합니다. 평가 문제로 정책을 조정하면 독립 평가로 취급할 수 없습니다. 원래 boolean 문제 다섯 개는 `exhaustive_public`이며 별도 heldout이 없습니다.

새 저장소에서는 연구를 실행하기 전에 제외된 데이터 파일을 한 번 생성합니다. 이 명령은 기존 연구 데이터와 catalog·비교 manifest도 다시 씁니다.

```powershell
go run ./cmd/preflight -generate
```

다음 명령은 실행 계획과 manifest SHA-256만 출력하며 모델을 호출하지 않습니다. `compare-dev-jev.json` 대신 `compare-eval-jev.json` 또는 `compare-all-jev.json`을 지정할 수 있습니다.

```powershell
.\scripts\run-research.ps1 -ManifestPath examples/research/compare-dev-jev.json -OutputDir output/research -MaxQuestions 12
```

실제 호출은 비용이 발생합니다. 예산과 입력을 확인한 후 명시적으로 `-Execute`를 추가합니다. 실행 전 모델 없이 참조 경로, 해시, 예산과 공개·보류 테스트를 검사하고 실패하면 중단합니다. `-PreflightOnly`는 이 검사만 수행합니다. 하나의 비교 실행이 `strict-greedy`, `beam`, `lds`, `levin`, `phs`, `mcts` 여섯 전략을 `paired-cross-over-v1` 순서와 세 반복으로 처리하며 `MaxQuestions`는 전체 실행의 상한입니다. `MaxCalls`와 `MaxCandidates`의 기본값은 각각 64와 8192이며, `MaxTokens`, `TimeoutSeconds`와 함께 검색별 한도입니다. 개별 문제의 더 엄격한 한도를 넘는 실험은 `-AllowBudgetOverride`를 명시해야 하며 변경 목록이 계획에 기록됩니다. 질문 수 제한은 금액 제한이 아닙니다. 실행 결과와 진행 이벤트는 각각 JSON과 JSONL로 남으며 취소나 예산 소진을 완료된 성공으로 해석하지 않습니다.

질문 묶음 ablation은 `-Ablation -DecisionBatchSize N`을 지정하고 manifest에 `lds`, `levin`, `phs`만 넣어 실행합니다. MCTS를 포함한 여섯 전략 기준 비교에는 배치 크기 1을 사용합니다. 결과에는 사용한 전략과 배치 크기를 함께 기록해 기준 비교와 구분합니다.

저장된 탐색 trace의 특정 판단에서 후보 ID와 순서 변화의 영향을 확인하려면 해당 이벤트의 `seq`와 trace 경로를 지정합니다. 이 명령은 Jev를 다시 호출하며 최소 7개 질문 예산이 필요합니다.

```powershell
go run ./cmd/headless audit --trace 'output/your-run.trace.jsonl' --seq 1 --max-questions 7
```

같은 joint frontier의 부모별 조건부 분포와 선택도 비교하려면 `--parent-local`을 추가합니다. 이때 질문 예산은 7에 강제 선택이 아닌 부모 수를 더한 값 이상이어야 합니다. 예를 들어 해당 부모가 셋이면 `--max-questions 10 --parent-local`을 지정합니다. 질문 수와 HTTP 요청 수는 서로 다른 지표입니다.

결과의 `known_usage`와 `known_estimated_cost`는 확인된 값의 소계이며, 전체 사용량이나 비용을 알 수 없으면 해당 전체 값은 `null`입니다.

[TypeSafe 모델 가격](https://docs.typesafe.ai/models)은 Jev 1.14 입력 100만 토큰당 $0.042이며 출력 토큰은 무료입니다.

참조 경로 도달성 검사, 후보 ID·순서 교란과 joint/parent-local 질문 비교는 전체 생성 성공률과 구분하는 probe 및 ablation입니다. 반복 실행 사이 모델 응답을 공유하지 않아야 합니다. 실제 평가 전 데이터 preflight와 질문 배치의 전역 예산 적용 여부를 확인하세요. 관측하지 못하는 서버 모델 CPU·시간과 사용량은 0으로 간주하지 않습니다. 자동 테스트나 참조 경로 결과만으로 Jev의 품질이나 속도 향상을 주장하지 않습니다.

자동 테스트와 실제 GPU 추론 검증은 별개입니다. 실제 Jev 인증 호출이나 전체 문제의 성능 측정 없이 모델 품질·속도 향상을 주장하지 않습니다. Windows 프로젝트 폴더와 Git 저장소 이름은 이 프로그램의 내부 모듈명 변경과 별도로 관리합니다.
